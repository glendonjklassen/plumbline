## Core + layout findings — ranked

### Correctness (fix first)

1. **`add_link` can write a user's link into a machine-generated suggestion**
   (`crates/core/src/weave.rs:546-566`, verified): the name match searches all
   loaded weaves including `weaves/suggested/`; rejecting that suggestion later
   deletes the user's own link. Fix: filter `is_suggested` out of the name
   match (helper already exists at weave.rs:572); never append to a suggestion.
2. **Layout orphans the verse number at a paragraph break**
   (`crates/layout/src/lib.rs:162-187`, verified): the number is placed and
   `line_started` set *before* token 0's `FLAG_PARA` triggers the newline — the
   number strands at the end of the previous line. Fix: check `tokens.first()`
   for FLAG_PARA before emitting the number; also wrap number+first-word as a
   unit. Add a snapshot test first (PROGRESS claims visual verification of ¶ —
   confirm actual behavior with the test).
3. **Typo-tier search order is nondeterministic**
   (`crates/core/src/search.rs:268-282`): HashMap iteration + stable sort on
   distance only → order shuffles across launches, contradicting the crate's
   determinism contract. Fix: sort by `(dist, word)`.
4. Smaller: `Config::from_wire` doesn't clamp the `active` pane index
   (`crates/core/src/config.rs:109-121` — shells index with it); `run_search`
   unwraps on corpus/index agreement (search.rs:164, :587); doc-comment error
   in `crates/core/src/reference.rs:83` ("65" should be 39).

### Performance (per-keystroke and startup paths)

5. **Phrase search allocates ~500k Strings per keystroke** for common bigrams
   (`search.rs:297-313`): candidates come from the rarest word's postings, and
   each candidate verse rebuilds all its lowercased tokens. Fix: intersect all
   postings first, then confirm consecutiveness comparing in place.
6. **Cache write deep-clones the whole corpus** (`corpus.rs:200-206`):
   serialize through a borrowing twin struct instead.
7. `note_idxs` re-lowercases ~7k margin notes on every query
   (`search.rs:173-181`): pre-lowercase once at load/index build.
8. Allocation hot spots: `SearchIx::build` clones the key String per token
   (~1.6M) instead of per distinct word (~13k) (search.rs:51,54);
   `OccurrenceIx` duplicates `SearchIx::lemma_ix` with heavyweight VRef
   postings (strongs.rs:54-67); `chapter_verses` allocates a String key per
   lookup (corpus.rs:159); `Link` PartialEq/Ord allocate six Strings per
   comparison (weave.rs:74-100); crossref line-split allocates a Vec per row
   × 344k (crossref.rs:44).

### Design / dedup

9. Triplicated dir-loader + name-lookup across weave/thread/tag (weave.rs:489,
   thread.rs:132, tag.rs:148, plus 5 copies of the case-insensitive lookup):
   extract a generic `load_json_dir` + `find_by_name` in store.rs. Exact
   duplicates: `weave_file_in` ≈ `store::slug`, `ref_label` ≈ `VRef::display`.
10. Test gaps: fuzzy tier (would have caught #3), multi-word fallback path,
    `HIT_CAP` behavior, layout number-orphan + overlong-word, config clamps,
    `add_link`-vs-suggestion (#1).

## Desktop shell findings (apps/desktop/src/main.rs) — ranked

### A. Responsiveness (biggest user-visible wins)

1. **`ensure_analytics` blocks the UI thread** (main.rs:264-295, wired at
   :1794): the first Ctrl+click in Full study synchronously loads embeddings +
   morphology and runs three corpus-wide builds inside the click handler —
   looks like a hang. Fix: build on a worker thread, deliver via
   `glib::idle_add_local`, show a "building analytics…" placeholder.
2. **`draw_pane` re-lays-out the chapter and deep-clones every verse on every
   draw** (main.rs:2694-2708): `.to_vec()` of all tokens + full Pango
   re-measure on every zoom tick / pin / highlight / resize. Fix: cache the
   `DisplayList` in `Pane` keyed by `(book, chapter, width, font_size)`; drop
   the `.to_vec()` by scoping the borrow.
3. **`zoom` writes config to disk per Ctrl+wheel tick** (main.rs:2130). Fix:
   debounce ~500 ms (close_request already persists on exit).
4. **Constellation recomputes page model + degree map per mouse-motion event**
   (main.rs:1376-1404; const_page :982, const_degrees :1097). Fix: cache in
   `ConstState`, invalidate on page/pin change.
5. **`draw_links` is O(all links × display-list items) per scroll frame**
   (main.rs:2821-2884; linear scan in `link_verse_y` :2909). Fix: bucket links
   by (book, chapter) at weave load; emit a verse→y map from `draw_pane`.
6. **`draw_concept_radial` recomputes English glosses per node per frame**
   (main.rs:788-797): memoize glosses in a HashMap on `State`.

### C. Portability — pure logic stranded in the GTK shell

Move to `crates/core` so the WinUI shell doesn't fork it (all GTK-free,
verified): `build_xrefs`/`build_links` (:164-196), the gloss pipeline
(`english_gloss`/`distil_gloss`/`normalise_word`, :3619-3693, tests move too),
chord/constellation view-model math (:2994-3005, :1046, :1114-1147). Biggest:
the study-panel builders (:3098-3805) fuse content decisions with Pango markup,
and `handle_link` (:2486) defines the action-URI scheme — extract a structured
"study card" model into core; shells only render it. **Highest-leverage
pre-Windows refactor; coordinate with the ARM64 effort.**

### D. Robustness / UX

- Timer-based races: 60 ms connector redraw (:1673) and 8 ms×120 poll for
  layout (:2016-2031) — replace with "layout ready" signaling from `draw_pane`.
- Esc doesn't close name/note prompts (:2277-2394); reading keys die when focus
  leaves the pane canvas (all nav lives on per-pane DrawingArea controllers,
  :1834-1876) — add a window-level fallback key controller; no Ctrl+F to focus
  search.
- `close_on_defocus` (:1534) also fires on Alt-Tab, discarding constellation
  state.
- Widget↔closure strong-ref cycles (e.g. :566-569, :1770-1876) — benign today,
  leaks under future per-pane teardown; use weak captures.
- `draw_pane` holds `borrow_mut` across GTK calls (:2665, :2811-2814) — latent
  `BorrowMutError`; scope the borrow.
- Minor: `update_title` can index-panic on empty panes (:1961); `highlight`
  never clears; `close_pane` doesn't decrement `active` when closing a pane
  before it (the active pane silently shifts); `make_link` ignores a third pin.

## FFI / rnd / hydrate / CI findings — ranked

(⚠ = directly relevant to the Windows ARM64 effort; hand off, don't collide.)

1. ⚠ **FFI data race (UB) between authoring calls and cross-thread readers**:
   the README promises `*const PureEngine` is shareable across threads for
   reads, but the 9 authoring entry points (`crates/ffi/src/lib.rs:932-1246`)
   do `as_mut()` → `reload_study()` (lib.rs:164-172), swapping study state with
   no synchronization. A C# shell authoring off the UI thread hits a real data
   race. Fix: RwLock around the reloadable study state (or document an
   exclusive-access requirement), plus a compile-time `PureEngine: Send + Sync`
   assertion.
2. ⚠ **Wire format has no version tag** (wire.rs): field renames produce zero
   binding diff, pass CI's drift guard, and break a typed C# decoder at
   runtime. Fix: export a `PURE_WIRE_VERSION` const (lands in the header via
   cbindgen) and commit golden serialized DTO samples diffed in CI.
3. **CI never builds featureless `pure-rnd`**: feature unification in the
   single test invocation (ci.yml:22) means the "simple build compiles no R&D"
   configuration is never compiled anywhere. Fix: add a separate
   `cargo test -p pure-rnd` step.
4. **`pure-hydrate copy` has silent data-loss paths**
   (`crates/hydrate/src/main.rs:114-164`): non-atomic `fs::copy` onto the live
   home (crash → truncated pack, tiers silently vanish); `--from X --to X`
   truncates sources via copy-onto-self; seeding blindly **overwrites
   user-authored weaves/threads/tags**. Fix: temp → rename per file, reject
   from==to, skip-or-back-up existing user dirs.
5. ⚠ **No tests run on Windows; built DLLs discarded**: add a native
   `windows-11-arm` (free for public repos) or `windows-latest` test job, and
   `actions/upload-artifact` for the cross-built DLLs so the shell effort gets
   per-commit artifacts.
6. **CI hygiene**: cargo-xwin compiled from source each run (use
   taiki-e/install-action); no fmt/clippy/MSRV jobs; push+PR double-runs (add a
   `concurrency` group with cancel-in-progress).
7. **`embed.rs` allocation storm on hot FFI paths**: `neighbours_by`
   (embed.rs:84-95) clones a String per vocab row; `similar_by` (:432-443)
   clones a VRef per verse (~31k) per "verses like this" call. Fix: score into
   `Vec<(usize, f32)>`, materialize only the k winners.
8. ⚠ **csbindgen only reads src/lib.rs** (pure-bindgen.rs:60): an extern fn
   added in a new module lands in the C header but silently vanishes from the
   C# shim — with no diff for CI to catch. Fix: feed all extern-fn files to
   csbindgen, or assert header/DllImport counts match in CI.
9. ⚠ **Release profile**: add `codegen-units = 1` + `strip = "symbols"`; do
   **NOT** add `panic = "abort"` — the FFI safety story depends on
   `catch_unwind` (lib.rs:253-262). Add a profile comment saying so.
10. **Bytes-opened engine probes CWD-relative `./bridge`** (lib.rs:125-126):
    nondeterministic + mild data-injection surface. Fix: skip the filesystem
    probe when `home` is None.
11. **`concept.rs` co-occurrence counting** clones two Strings per pair
    increment over the whole corpus (concept.rs:78-91): intern codes to u32,
    key by packed u64.
12. **Dead feature flags**: `keyness`/`trust` gate no code but `capabilities()`
    reports them true (rnd/src/lib.rs:57-66) — a contract-honoring UI would
    show empty panels. Drop until implemented.

Also: `crates/ffi/Cargo.toml` builds `pure-rnd` with
`bridge embeddings morphology` but **not `concept`**, while the desktop shell
includes `concept` — a WinUI shell over the DLL would silently lack the
collocation ("appears alongside") tier. ⚠
