# Plumbline's ART baseline profile — HAND-AUTHORED. Read that first.
#
# WHAT IT DOES. AGP compiles this file (plus the profiles Compose/AndroidX ship
# inside their AARs) into assets/dexopt/baseline.prof, and
# androidx.profileinstaller writes it into the app's reference profile on first
# launch. From then on ART runs these methods AOT-compiled instead of
# interpreting them while JIT catches up — the usual 20–40% off a Compose cold
# start. That library dependency is not optional here: a cloud profile is
# something the Play Store installs, this product ships a sideloaded APK from a
# GitHub Release on purpose, and without profileinstaller the profile in the APK
# is inert. (It already was: every release through v0.35.0 shipped an 8,175-byte
# baseline.prof of merged library profiles with nothing on the device to read it.)
#
# WHAT WOULD REPLACE IT. A real profile is MEASURED, not written by hand: a
# :macrobenchmark module running BaselineProfileRule over a scripted cold start
# on a real device, whose output is exactly the classes and methods that start
# actually touched, with ART's own hot/startup flags. There is no device in this
# build environment, so this file is reasoned from the startup path instead —
# MainActivity → asset extraction → engine open → LoadCoreData → the reader's
# first chapter layout and paint. When a device run exists, REPLACE THE WHOLE
# FILE with its output; do not merge a generated profile into this one by hand,
# and do not trust these flags over measured ones.
#
# WHAT IS DELIBERATELY ABSENT. Compose, Activity, Lifecycle, Material3 and the
# rest of AndroidX ship their own baseline profiles and AGP merges them in. A
# hand-copied duplicate of someone else's profile only rots.
#
# FORMAT (profgen). `Lpkg/Class;` = load this class during startup.
# `HSPL<class>-><method>` = Hot, Startup, Post-startup. `**` is a wildcard, and
# it is what keeps this file from listing Compose's generated lambda classes
# (`ReaderPaneKt$$ExternalSyntheticLambda7`, renumbered by every recompile) or
# every `$$serializer`. A rule that matches nothing is dropped silently — safe
# against renames, but also silent about them.

# ── the process: Activity → writable home → engine → first frame ────────────
# onCreate sets XDG_CONFIG_HOME, loads the cdylib, extracts assets and opens the
# engine; the free functions in MainActivityKt (copyAsset / writeThroughTemp /
# sameStream / shouldSeed / warmPlan) copy 32,713,184 bytes of assets/data +
# assets/bridge on a first install, and re-run the seed checks every launch.
Ldev/plumbline/MainActivity;
HSPLdev/plumbline/MainActivity**->**(**)**
HSPLdev/plumbline/MainActivityKt**->**(**)**

# ── the JNA binding: the whole ABI surface is on the startup path ────────────
# Every engine call in this shell goes through the PlumblineNative proxy, and
# the layout call also crosses back per word through MeasureCallback. JNA
# publishes no baseline profile of its own, and its proxy/Structure machinery is
# reflection-heavy — exactly the code JIT is slowest to reach.
